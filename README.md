# LINUX SB 用户资料卡

一个用于 [LINUX SB](https://linux.sb/) 的 Chrome 扩展。点击用户头像时，在头像附近展开资料卡，查看用户信息后继续阅读当前帖子；需要访问用户主页时，再点击卡片内的入口。

当前版本：`0.1.0`。采用 Chrome Manifest V3，仅在 `https://linux.sb/*` 页面生效。

## 功能介绍

| 内容 | 展示方式 |
| --- | --- |
| 头像、昵称、UID | 昵称最多显示一行，超出省略；鼠标停留可查看完整昵称 |
| 用户状态 | 在昵称旁显示完整的 `user-state-tags` 容器及其子标签，例如「禁言」 |
| 称号 | 保留站点称号样式、编号及动画，隐藏 `gacha-title-icon`；最多两行，超出横向滚动 |
| 用户组、积分 | 展示用户主页提供的信息，用户组复用原生徽章 |
| 个人简介 | 独立展示，长内容可在区域内滚动 |
| 帖子签名 | 与个人简介分开展示，从该用户的可访问帖子中提取 |
| 页面入口 | 个人主页、主题、回帖、收藏；主页提供「私信TA」链接时显示私信按钮 |

### 交互行为

- 点击头像打开资料卡，再次点击同一头像收起。
- 点击卡片外部、关闭按钮或按 `Esc` 关闭；按 `Esc` 后焦点返回原头像。
- 支持键盘聚焦头像后按回车打开；保留中键及修饰键点击的浏览器默认行为。
- 普通昵称链接仍按原站点行为跳转，只拦截符合条件的头像链接。
- 加载时优先显示已有头像、昵称和状态，其余资料使用骨架屏；失败后提供重试入口。
- 异步资料更新保留卡片容器，头像地址不变时复用头像节点，避免重复播放入场动画。
- 卡片自动避让窗口边缘；原头像滚出可视区域后关闭。
- 支持页面动态新增的头像，无须逐个绑定事件。

## 安装与使用

要求 **Google Chrome 114 或更高版本**。当前通过 GitHub Releases 提供扩展安装包，尚未上架 Chrome 应用商店。

1. 打开本项目的 [Releases 下载页面](https://github.com/earlySummerCx/linuxsb-plugin/releases/latest)，下载最新版本的 `linuxsb-user-card-v0.1.0.zip`（不要下载下方自动生成的 Source code）。
2. 将 ZIP 解压到一个固定文件夹，安装后请保留该文件夹。
3. 打开 Google Chrome，点击右上角 **⋮ → 扩展程序 → 管理扩展程序**，也可以直接在地址栏输入 `chrome://extensions/`。
4. 开启页面右上角的 **开发者模式**。
5. 点击 **加载已解压的扩展程序**（部分版本显示「加载未打包的扩展程序」），选择刚才解压后包含 `manifest.json` 的文件夹。
6. 确认「LINUX SB 用户资料卡」已启用，打开或刷新 [Linux SB](https://linux.sb/)，点击用户头像即可使用。

扩展没有工具栏弹窗或设置页，所有操作直接在 Linux SB 页面完成。下载 ZIP 后需要解压并加载，不能直接把 ZIP 当作 Chrome 应用商店扩展安装。

### 更新扩展

从 Releases 下载新版本并解压，将文件覆盖到原安装文件夹。在 Chrome 扩展管理页点击「LINUX SB 用户资料卡」的重新加载按钮，再刷新 Linux SB 页面。

### 卸载扩展

打开 Chrome 的「管理扩展程序」，找到「LINUX SB 用户资料卡」，点击「移除」。

## 样式复用方式

卡片布局使用 Shadow DOM 隔离，避免卡片自身的 CSS 影响网站。称号、用户组和用户状态通过 **light DOM + 命名 slot** 放入卡片，保留站点原有类名，让网站 CSS 直接生效。

- 不在插件中重新定义称号、用户组或状态标签的颜色、边框。
- 称号保留所需的站点祖先结构，使原站点的帖子称号样式能够匹配。
- 完整保留 `user-state-tags` 的状态分组及子标签类名。
- 复制前过滤可执行内容和不安全属性，保留允许的标记与颜色变量。
- 卡片背景、文字等读取站点主题变量；深色模式的完整视觉验收尚未完成。

## 数据来源与缓存

资料通过当前浏览器登录态请求同源用户主页 `/user/{UID}`，解析头像、昵称、状态、称号、用户组、积分、简介和私信入口。扩展不会绕过站点访问权限。

帖子签名按以下顺序获取：

1. 优先读取当前页面中作者 UID 匹配的帖子签名。
2. 当前页面没有可用帖子时，使用有效的签名缓存。
3. 仍无法获取时，按需请求用户主页列表中的第一篇匹配主题，从该作者的帖子中提取签名。

不会遍历用户全部帖子。签名来自可访问的帖子样本，不保证代表用户当前设置；无法获取时显示「暂未获取到签名」，不会直接认定用户未设置签名。简介和签名均按纯文本显示，不渲染其中的 HTML 或嵌入媒体。

资料缓存保存在当前页面内存中，有效期 **5 分钟**，最多 **100 位用户**；用于签名解析的主题页面缓存最多 **20 个**。刷新页面后缓存清空。同一资料的并发请求会合并，迟到的响应不会覆盖后来打开的用户资料。

扩展没有第三方后端或分析上报，不申请 `cookies`、`storage`、`tabs` 权限，也没有后台脚本。页面请求携带同源登录态，但扩展不通过 Cookie API 读取登录凭据。头像仍按站点提供的资源地址加载。

├── src/
│   ├── core.js             # 资料解析、原生标记过滤、URL 校验和缓存

├── scripts/

│   ├── preview.mjs         # 本地预览服务
│   └── prepare-demo.cjs    # 开发样本生成工具，非构建必需步骤
├── tests/
│   ├── core.test.cjs       # 解析、样式标记、URL 和缓存测试
│   └── app.test.cjs        # 点击、异步更新、骨架屏等交互测试
├── assets/                 # 关闭图标及其许可证
├── demo/                   # 本地开发样本
├── dist/                   # 可直接加载的 Chrome 扩展

├── package-lock.json

`work/` 为本地临时检查材料，已配置 Git 忽略，不参与扩展构建。

## 验证状态与限制

目前已通过 **15 项自动化测试**，覆盖资料解析、访问边界、缓存、异步切换、动态头像、骨架屏、更新时保留卡片节点，以及原生称号和完整状态标签的保留。

已在用户 Chrome 的实际 Linux SB 页面验证头像点击拦截、资料读取、原生徽章、长昵称省略、窗口边缘定位、原生状态标签、关闭按钮点击、`Esc` 关闭及主题入口跳转。

以下项目仍需实际站点视觉验收：

- 真实多称号用户的两行横向溢出。
- 深色主题、完整窄屏布局和弱网加载效果。

详细记录见 [design-qa.md](design-qa.md)。

资料解析依赖当前站点的 HTML 结构和 CSS 类名；站点改版后可能需要同步调整选择器。私信按钮只使用主页实际提供的链接，收藏等目标页面是否可访问由网站决定。

## 常见问题

**点击头像仍直接跳转怎么办？**

确认扩展已启用、加载的是解压后包含 `manifest.json` 的文件夹，并在重新加载扩展后刷新站点页面。当前仅支持 `https://linux.sb/*`；站点新增的头像结构可能需要补充适配。

**为什么没有私信按钮或签名？**

私信按钮取决于主页是否提供对应链接；签名取决于能否访问并匹配该用户的帖子。权限限制、网络失败或没有可用帖子都可能导致字段缺失。

**为什么称号样式会随网站变化？**

扩展直接复用网站原生样式，未维护独立的称号配色或边框规则。站点样式调整会反映到资料卡中。
